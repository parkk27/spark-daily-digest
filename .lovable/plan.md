# Trends Page Redesign — Executive Intelligence Dashboard

Transform `/trends` from a flat list of topic cards into five insight-oriented sections, each explaining **why** a trend matters and what it implies strategically. Reuse already-fetched snapshot data — no new API calls on page load.

## Sections (in order)

1. **Biggest Shift Today** — single hero card. The topic with the largest absolute `change`. Shows direction arrow, delta, and a one-line strategic implication.
2. **Fastest Growing Technologies** — top 3 topics with `status: growing`, sorted by `change` desc. Compact rows with mention delta + why-it-matters line.
3. **Vendor Momentum** — filters trends to vendor topics (`databricks`, `snowflake`, `aws`, `google`, `microsoft`, `bigquery`, `fabric`, `emr`, `redshift`, `synapse`). Shows each vendor's net momentum (today vs yesterday) with up/down indicator.
4. **Emerging Signals** — topics with `status: new` (appeared today, not yesterday). Strategic framing: "early signal to watch".
5. **Declining Topics** — `status: declining`, sorted by largest drop. Framed as "losing mindshare".

Each section card contains:
- Section title + icon
- 1–3 topic entries with: topic name, direction indicator (↑/↓/✦), mention delta (e.g. `2 → 5`)
- **Why it matters** — one sentence per topic generated by AI, grounded in the latest snapshot's article headlines/summary

## Where the "why" lines come from

A new edge function `spark-trend-insights` takes the latest snapshot (already in `useSparkData` cache) and returns a `{ topic: string, why: string, implication: string }[]` map. Called once per session, cached via React Query (24h staleTime keyed by snapshot date). Uses `google/gemini-3-flash-preview` with a tight prompt:

> "For each topic below, write ONE sentence (max 20 words) explaining WHY it's trending based on the provided articles. Focus on strategic/architectural implications. No fluff."

Input: top ~10 movers + their tag-matched article titles from `snapshot.articles`. Output: JSON via `responseFormat: json_schema`.

If the function fails or is slow, the page renders without the "why" lines — sections still work with structural data alone.

## Layout

Single column, max-w-5xl, mirrors HomePage card style (`rounded-lg border border-border bg-card p-6`). No charts, no comparisons — minimal and executive-friendly per MVP scope.

## Technical Changes

**New files**
- `supabase/functions/spark-trend-insights/index.ts` — POST takes `{ date, trends, articles }`, returns `{ insights: { topic, why }[] }`. JSON-only, no streaming. Verify_jwt off.
- `src/hooks/useTrendInsights.ts` — `useQuery` keyed by snapshot date; calls the edge function with trimmed payload.
- `src/components/trends/BiggestShift.tsx`
- `src/components/trends/TrendSection.tsx` — generic section with icon/title/rows
- `src/components/trends/VendorMomentum.tsx`

**Edited**
- `src/pages/TrendsPage.tsx` — replace grid of `StatusBadge` cards with the five new sections. Derive sections from `data.trends` via small pure helpers (`getBiggestShift`, `getFastestGrowing`, `getVendorMomentum`, `getEmergingSignals`, `getDeclining`) defined inline or in `src/lib/trends.ts`.

**Reused as-is**
- `useSparkData` (snapshot already cached)
- `StatusBadge`, design tokens, dark theme

## Out of scope (per MVP memory)
- No charts or sparklines
- No vendor-vs-vendor comparison tables
- No historical multi-day trend graphs
- No personalized watchlists

## Open question
Should the "why" insights be pre-computed and stored on the daily snapshot (cheaper, one generation per day), or generated on-demand per session (simpler, no migration)? Default in this plan: on-demand with React Query caching. Confirm or switch.

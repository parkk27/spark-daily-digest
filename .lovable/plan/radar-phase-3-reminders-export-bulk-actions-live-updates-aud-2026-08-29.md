# Radar Phase 3 — Reminders, Export, Bulk Actions, Live Updates, Audit Trail

Five additive enhancements on top of the existing Action Radar lifecycle. No changes to the recommendation engine, decision values, or existing tables' access rules.

## 1. In-app review reminders

- A notifications bell in the top nav showing a count of signals whose review date is due or overdue (and actions past their due date).
- Clicking it opens a panel listing each due signal with its lane, days overdue, and a jump straight into the decision workspace.
- Radar cards and the "Reviews due" tile keep their existing overdue styling; overdue items sort to the top of their lane.
- Dismissing a reminder is per-signal and remembered locally until the review date changes.
- No email in this phase (chosen: in-app only). The existing Settings email preference is left untouched.

## 2. Export for stakeholders

- An "Export" control in the Radar header with two options:
  - **CSV** — one row per visible signal: title, lane, owner, priority, confidence, decision, reason, action, action owner, due date, review date, outcome, status, evidence count, source date. Plus a header block with the lifecycle counts.
  - **PDF** — a clean print view (browser print-to-PDF) titled with the date and current filters, showing the lifecycle count summary, emerging themes, and the selected signals as compact rows.
- Export respects the current filters and, when signals are selected via bulk mode, exports just the selection.

## 3. Bulk actions in My Radar

- A selection mode on the Radar list: checkbox per card, "select all visible", and a sticky bar showing the count.
- Bulk operations on the selection:
  - Mark reviewed (sets/extends a review date)
  - Set decision to Monitor or Investigate (with one shared reason, required)
  - Create an action (shared action text, owner, due date)
- Each item is written through the existing decision path, so history archiving, status mirroring, and RLS behave exactly as for single edits. Progress and a per-item success/failure summary are shown; partial failures are reported rather than silently swallowed.

## 4. Real-time radar change notifications

- Subscribe to inserts/updates on recommendations so a banner appears when new or escalated signals arrive: "3 new signals, 1 escalated — Refresh".
- Refresh applies the new data without a page reload and clears the banner.
- Signals that changed since your last view are marked with a "Changed" chip until reviewed; escalations (moved into Act now) get an "Escalated" chip.
- Falls back silently to the existing manual refresh delta if the live channel is unavailable.

## 5. Audit trail

The append-only history table already records every decision change, action edit, and outcome. This phase surfaces it:

- A "History" section on each signal card (expandable) showing each entry: what changed, the decision at the time, the reason and change reason, action/owner/due, outcome, and the timestamp.
- Entries render as a timeline with the current state at the top.
- A "Decision history" tab in the decision workspace so the trail is visible while re-deciding.

## Technical notes

- New: `src/lib/radarReminders.ts` (due/overdue derivation), `src/lib/radarExport.ts` (CSV builder + print view data), `src/components/radar/NotificationsBell.tsx`, `src/components/radar/BulkActionBar.tsx`, `src/components/radar/SignalHistory.tsx`, `src/components/radar/RadarExportDialog.tsx`.
- Extend `useRecommendations.ts` with a bulk decision mutation that loops the existing `upsertDecision` logic, and a history hook that fetches by signal key (already present) plus action/outcome columns.
- Realtime uses a Supabase channel on `recommendations`; requires enabling replica identity/publication for that table via one small migration. No new tables.
- PDF is generated by a dedicated print stylesheet + `window.print()` — no new dependency.
- Unit tests for reminder derivation, CSV row mapping, and bulk-result aggregation; existing 28 tests must stay green.
